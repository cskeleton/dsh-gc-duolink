# ADR-001: 纯插件初始选模及实验版本历史处理

状态：已接受。日期：2026-10-13。适用版本：0.5.0。

## 背景

旧任务路由实验同时实现任务状态机、fallback、任务范围模型覆盖及宿主 task-host 扩展。复杂性和宿主依赖超出了用户最终选择的范围：只给新建普通顶层会话配置初始模型。

选模开发前的功能基线是 `42abec427c26ef1448728d49f720bf3139021292`，包含要保留的 UI 和双向自动唤醒。插件实验保存在 `329f4f3…549a1d7` 的 19 个提交中；旧 DSH 扩展在另一个仓库的未提交工作区中，不能把插件 Git 历史误当成宿主改动的备份。

## 决定

- 通过官方 DSH 0.2.0-rc.2 的 native proof 后，以前向源码调整恢复上述功能基线，再加入小型初始选模实现。保留旧提交，不 reset、rebase 或删历史；本次提交在 `549a1d7` 后明确取代实验功能。
- 插件只使用公开 Session prepare、原生 model/selection 事件、持久化接口和 native create/adopt。原生 controller 是唯一运行期模型 owner；不改应用默认，不增加第二套选择器。
- 移除 tracked-task 引擎、任务域服务、任务 RPC/UI、任务决策工具、fallback 和 `./tasks` 导出。旧任务扩展测试退休，不改断言以假装被取消的能力仍可用。
- 旧计划和审查保留在原路径并加历史标记，便于追溯。旧迭代路线图暂停，不作为当前实现清单。当前契约以中英文 README、IMPLEMENTATION 和 VERIFICATION 为准。
- 不在本插件提交中提交、撤销或清理 DSH 仓库里的扩展。宿主工作区还包含无关开发改动，后续清理需要单独授权并逐 hunk 核对，不能整文件恢复。

## 数据与升级后果

普通互联版 0.4.1 可覆盖更新至 0.5.0，互联关系与历史消息保留。实验版也使用过 0.4.1，升级资格不能只按版本号判断。

带 statusKind/taskStatus 的遗留报告保留并阻止投递、唤醒和显式重放；未标记任务邮件、宿主专属事件与任务域不自动迁移。实验 profile 切换前必须单独检查，不能通过删数据制造兼容。

0.5.0 的官方 Web 路线已有 native 和 packed 请求证据，Electron 和付费模型不因源码兼容或用户“初步测试通过”而视为完整验收。

## 未采用的方案

在现有任务引擎上仅关闭参数会继续保留宿主依赖和旧运行语义；逐段维护该架构没有实际收益。修改官方宿主补齐接口偏离纯插件目标。重写或删除旧提交会丢失审查依据，且不能清理另一仓库的工作区，因此均未采用。
